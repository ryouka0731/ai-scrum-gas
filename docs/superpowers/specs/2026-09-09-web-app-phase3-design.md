# AI Scrum Web アプリ 第3段階 設計（対象で分けるタブと、スプリント・障害物のビュー）

## 背景

第1・第2段階で「やること（PBI）」を見て・動かして・直せるようにした。しかし
**アプリにあるのはカンバン1枚だけ**で、ベロシティもバーンダウンもロードマップも障害物も
スプレッドシートにしか無い。

第1段階の設計にはこう書いた。

> 人間は生のスプレッドシートを見ない。アプリだけを見る

**これは成立していない。** 段階を切ったとき、他のビューをアプリへ持ってくる計画を
落としていた。本設計でそれを埋める。

## 段階の位置づけ

| 段階 | 内容 | 状態 |
|---|---|---|
| 第1段階 | 双方向同期の基盤 + カンバン | 完了 |
| 第2段階 | PBI の作成・編集・削除 + UI 刷新 | 完了（PR #2） |
| **第3段階（本設計）** | **対象で分けるタブ + スプリント・障害物のビュー + 用語の整理** | 本設計 |
| 第4段階 | 障害物の作成・編集・解決 | 未着手 |
| 第5段階 | コメント・議論のスレッド | 未着手 |
| 第6段階 | 変更履歴と差分表示 | 未着手 |

**スプレッドシートは残す。** アプリが主、シートは控えと Excel への書き出し口、そして
メモ列の置き場として残る。同期もメニューもトリガーもそのまま。

## 概念モデルからの導出

`2026-09-09-concept-model.md` の対象は **やること / スプリント / 障害物** の3つ。
ベロシティもバーンダウンもロードマップも、**スプリントという対象の見え方**であって
対象そのものではない。

**タブは対象の名前にする。動作はボタンにする。** ビューの切り替えはタブの中に置く。

```
┌────────────────────────────────────────────────┐
│ AI Scrum          [やること] スプリント  障害物   │
├────────────────────────────────────────────────┤
│ 未着手 4 ・ 進行中 2 ・ 完了 8 / 全 14（38 pt）   │  ← 要約
├────────────────────────────────────────────────┤
│ [盤面] 一覧  完了                                │  ← 見え方
│ ┌──────┬──────┬──────┬──────┬──────┐          │
│ │ New  │Ready │進行中 │Review│ Done │          │
└────────────────────────────────────────────────┘
```

**ダッシュボードはタブにしない。** 「全部の要約」は対象ではないので、対象と同じ階層に
置くと非 MECE になる。各タブの頭に、その対象の要約として分散させる。

**同期ログもタブにしない。** 利用者の関心事ではなく運用の記録である。シートに残す。

## タブとビュー

| タブ（対象） | ビュー（見え方） | 元データ |
|---|---|---|
| **やること** | 盤面（カンバン。第2段階のもの） | `product_backlog.csv` |
| | 一覧（表。全項目が見える） | 同上 |
| | 完了 | `product_backlog_done.csv` |
| **スプリント** | バーンダウン | 最新 `sprintXXX/sprint_backlog.md` の「バーンダウン」表 |
| | ベロシティ | `velocity.csv` |
| | ロードマップ | `product_backlog.csv` + `velocity.csv` |
| **障害物** | 一覧（未解決 / 解決済） | `impediment_log.csv` / `impediment_log_resolved.csv` |

**未解決と解決済は `status` 列ではなくファイルで分かれている。** 既存の
`buildImpedimentGrid(openRows, resolvedRows, notesByKey)` も2つの配列を受け取る形である。
第4段階で「解決」を実装するときは**2ファイルにまたがる書き戻し**になり、PBI には無い形に
なる（第3段階では読むだけなので影響しない）。

### 各タブの要約

| タブ | 要約に出すもの | 集計元 |
|---|---|---|
| やること | ステータス別の件数とポイント、合計 | `product_backlog.csv`（`buildDashboardGrid` と同じ計算） |
| スプリント | 最新スプリントのゴール | `sprintXXX/sprint_backlog.md` の「スプリントゴール」節 |
| | 計画 / 完了 / 持ち越しポイント | **`velocity.csv` の最新行**（`planned_points` / `completed_points` / `carried_over_points`） |
| 障害物 | 未解決の件数、解決済の件数 | **`impediment_log.csv` / `impediment_log_resolved.csv` の行数**（`isImpedimentPlaceholder` で雛形行を除く） |

**`buildDashboardGrid` はそのまま使えない。** あれが集計するのは
スプリントゴール・PBI のステータス別件数とポイント・警告だけで、
**スプリントの計画/完了/持ち越しも、障害物の件数も集計していない。**
`pure_summary.js` に3つの要約を作る（既存の集計ロジックは参考にするが、`pure_grid_report.js`
は触らない。あれはシートの同期が使い続ける）。

## 第3段階での書き込み

**やること以外は読み取り専用。** 障害物の作成・編集・解決は第4段階。

書き込みが増えるのは次の1点だけである。

- **スプリントをプルダウンにする**（後述）。書き込む列は `sprint` で、既存の
  `apiUpdatePbi` をそのまま使う。新しい API は足さない

## スプリントを選ばせる

現在 PBI のスプリントは**自由入力のテキスト**である。真実の源泉は既に `velocity.csv` に
あるにもかかわらず、そこと繋がっていない。

実害がある。

- 打ち間違いが幽霊スプリントを作る（`sprint002` / `sprint 002` / `Sprint002`）
- `velocity.csv` に無い名前を書くと、その PBI は**ロードマップから消える**。
  しかもエラーは出ない
- `normalizeSprint()` という表記ゆれ吸収の関数が存在する。**自由入力を前提にした
  後始末**で、選ばせれば要らない

**プルダウンにする。** 選択肢は次の順で組み立てる。

1. 「未割り当て」（空文字）
2. `velocity.csv` の実在スプリント（`realSprints()` が返すもの）
   — **並び順は `velocity.csv` の行順に従う。** `realSprints()` は絞り込むだけで
   並べ替えないため、「名前の昇順」を仕様にすると実装が仕様と食い違う。
   ファイルの行順はスプリントの時系列そのものなので、そのほうが読みやすい
   — **この関数は `pure_grid_board.js` にあるが `module.exports` に含まれていない。**
   公開する必要がある（GAS 上では同じグローバルなので動くが、node のテストから見えない）
3. **今の値が 1・2 のどれにも当たらない場合、その値を一時的な選択肢として末尾に足す**

3 は既存値を壊さないためである。第2段階で語彙外の `priority` を扱ったのと同じ方針。
一時的な選択肢には「（`velocity.csv` に無い）」と添え、保存すれば正規の名前に直せる
ことが分かるようにする。

`normalizeSprint()` は**既存データのために残す**。新しく作られる表記ゆれは無くなる。

## 用語

### `size` は「ストーリーポイント」

現在の表示は「サイズ」で、何を指すか伝わらない。**「ベロシティ」は使わない。** 別物である。

| 言葉 | 何を指すか | どこにある |
|---|---|---|
| **ストーリーポイント** | その項目1つの相対見積り | `product_backlog.csv` の `size` 列 |
| **ベロシティ** | チームが1スプリントで消化できた量の合計 | `velocity.csv` の `completed_points` |

本段階でベロシティのビューを作るため、同じ言葉を PBI の欄に使うと
「このカードのベロシティは5」「このスプリントのベロシティは23」が並んで混乱する。

「工数」も使わない。工数は人時・人日（絶対値）だが、`size` は時間ではない。

- カード: `◇ 5 pt`
- パネルの見出し: 「ポイント」
- ヒント: 「相対見積り。ベロシティは完了したポイントの合計」

**CSV の列名 `size` は変えない**（ローカルの Claude Code と共同所有のため）。表示だけ。

### 専門用語には補足を付ける

スクラムには専門用語が多い。**補足はデフォルトで付ける。**

用語と説明は `gas/pure_glossary.js` に**1か所だけ**持つ。同じ言葉の説明が画面ごとに違うと、
それ自体が混乱のもとになる。

対象: ストーリーポイント / ベロシティ / バーンダウン / ロードマップ / スプリント /
障害物 / 受入基準 / 各ステータス（New・Ready・In Progress・Review・Done）/
各優先度（Critical・High・Medium・Low）。

**見せ方は場所で使い分ける。**

| 場所 | 見せ方 |
|---|---|
| パネルの入力欄（余白がある） | **常に見える一行**。既存の `.field .hint` をそのまま使う |
| カード・列見出し・表のヘッダー（余白がない） | **押すと開く補足** |

「押すと開く」形にするのは、**マウス・タッチ・キーボードで同じように使えるため**である。
カーソルを当てただけでも開くので、マウスの利用者は押さなくてよい。第2段階でタッチ端末に
対応した（ステータスのプルダウン）ので、カーソルだけに頼る形は採らない。

補足は**モーダルにしない**。開いている間も盤面は操作できる。Escape と、外側を押すことで
閉じる。読み上げに伝わるよう、開閉の状態を要素に持たせる。

## メモ列はアプリに出さない

メモ列があるのは**バックログと障害物のシートだけ**である（`BACKLOG_HEADERS` と
`IMPEDIMENT_HEADERS` にのみ `'メモ'` が付く）。**完了バックログには無い。**
人はそこに直接書き込める。

**Web アプリからは読めない。** `oauthScopes` が `spreadsheets.currentonly` で、
Web アプリの実行にはスプレッドシートの束縛が無いためである。

**これは制約であって選択ではない。** メモを使いたい人はシートを開く。
`README.md` にそう書く。

## アーキテクチャ

第1・第2段階の方針を維持する。

- `pure_*.js`: GAS API に依存しない純関数。**ビューのデータ組み立てはここ**
- `gas_*.js`: `DriveApp` への薄い入出力
- `web_app.js`: API のエントリポイント
- `kanban.html`: 画面

### 追加するもの

| ファイル | 責務 |
|---|---|
| `gas/pure_glossary.js` | 用語と説明。1か所の真実の源泉 |
| `gas/pure_view_backlog.js` | 一覧・完了のビューのデータ |
| `gas/pure_view_sprint.js` | バーンダウン・ベロシティ・ロードマップのビューのデータ |
| `gas/pure_view_impediment.js` | 障害物の一覧のビューのデータ |
| `gas/pure_summary.js` | 各タブの要約 |

**既存の `pure_grid_*.js` は触らない。** あれはスプレッドシートの2次元配列を作るもので、
シートの同期が使い続ける。**アプリ用のデータ組み立ては別に持つ。** 同じ関数に2つの
出力形式を持たせると、どちらかを変えたときにもう一方が壊れる。

### API

読み取りのビューが増えるが、**API は1つに集約する。**

```
apiGetView(name) → { ok: true, view: {...} } | { ok: false, message }
```

`name` は `board` / `list` / `done` / `burndown` / `velocity` / `roadmap` / `impediment`。

既存の `apiGetBoard` は `apiGetView('board')` に置き換える。**`gas/kanban.html` の
`load()` が呼んでおり、その周辺には `writeSeq` による会計のコメントが2箇所ある。
置き換えでその仕組みを壊さないこと**（読み取り中に書き込みが確定したら古い board を
描かない、という第2段階の修正である）。

タブごとに API を増やすと、公開関数が7つ増える。`google.script.run` は全グローバル関数を
ブラウザへ公開するため、**公開面は小さいほどよい**。

要約は各ビューの応答に含める（タブを開いた時点で1往復で済む）。

## 読み取りの失敗

ファイルが無い、壊れている、という状況は普通に起きる。

- `sprint_backlog.md` が無い、または「バーンダウン」の表が無い → `buildBurndownGrid` は
  `null` を返す。**「まだありません」と出す。エラーにしない**
- `velocity.csv` が雛形のまま → ベロシティは空。ロードマップの帯も出ない。
  **「`velocity.csv` にスプリントが登録されていません」と出す**
- `impediment_log.csv` が無い → 「障害物はありません」

**どれも他のタブを巻き添えにしない。** ビューごとに独立して失敗する。

## テスト

`node --test` で検証するもの（すべて純関数層）。

| 対象 | 確認する内容 |
|---|---|
| 用語集 | すべての用語に説明があること。画面で使う語が用語集にあること |
| スプリントの選択肢 | 実在スプリント + 未割り当て。既存値が無ければ末尾に足されること |
| 一覧・完了のビュー | プレースホルダ行が除かれること。列の順序 |
| スプリントのビュー | 元データが無いとき `null` を返すこと |
| 障害物のビュー | 未解決と解決済が分かれること |
| 要約 | 件数とポイントの集計 |

DOM シム（`gas/tests/kanban_harness.js`）での検査も広げる。

- **タブとビューの切り替えで、盤面の状態が失われないこと**
- **補足がマウス・タッチ・キーボードのどれでも開くこと**
- **補足を開いている間も盤面が操作できること**（モードレス）
- 読み取りに失敗したビューが、他のタブを巻き添えにしないこと

`[hidden]` と同じく、**シムが CSS を評価しない**ことに注意する。補足の位置や重なりは
静的検査か実ブラウザで確かめる。

## 実機で確かめること
