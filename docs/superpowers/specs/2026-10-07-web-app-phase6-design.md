# Web アプリ 第6段階 設計: 変更履歴と差分表示

## 背景

PBI や障害物が「いつ・誰に・どう」変えられたかを、画面から辿れない。Drive の版の履歴はファイル単位で、
どの PBI のどの項目が変わったかは読み取れない。本段階で、Web アプリからの変更を項目単位で記録し、
パネルで差分として見られるようにする。

## 段階の位置づけ

| 段階 | 内容 | 状態 |
|---|---|---|
| 第1〜5段階 | 同期・PBI・タブとビュー・障害物・コメント | 完了（PR #1〜#7） |
| **第6段階（本設計）** | **変更履歴と差分表示** | 本設計 |

## 記録するもの・しないもの

**記録する:** Web アプリからの書き込みすべて。

| 対象 | 操作 |
|---|---|
| PBI | 作成・項目の変更（状態の変更を含む）・削除・削除の取り消し |
| 障害物 | 作成・項目の変更・解決・解決の取り消し |
| コメント | 追加・削除・削除の取り消し（本文は記録しない。コメント自体が残るため） |

**記録しない:**

- `updated_at` の変化（毎回変わるので雑音になる）
- ローカルの Claude Code が CSV を直接書き換えた変更。Web アプリは書き込み時にしか差分を取れないため。
  エージェント自身の作業記録はスプリントの成果物（`sprint_backlog.md` 等）に残る。画面には
  「Web アプリからの変更だけを記録しています」と書く
- 共有スプレッドシートへの同期

## 保存先: `scrum/change_log.csv`

追記だけのファイル。列は `id,at,actor,target_id,action,field,before,after`。

| 列 | 内容 |
|---|---|
| `id` | `CHG-` + 8桁の16進（UUID 由来。同じ書き込みで出た行は別々の id） |
| `at` | `YYYY-MM-DD HH:mm:ss`（サーバの時刻。同じ書き込みの行は同じ値） |
| `actor` | ログイン中のメールアドレス。取れなければ空 |
| `target_id` | `PBI-\d+` / `IMP-\d+` |
| `action` | `create` / `update` / `delete` / `restore` / `resolve` / `unresolve` / `comment_add` / `comment_delete` / `comment_restore` |
| `field` | `update` のときの列名（`title` 等）。それ以外は空 |
| `before` / `after` | `update` のときの変更前・後の値。それ以外は空 |

1回の書き込みで変わった項目ごとに1行（`update` は項目数だけ行が出る）。`create` / `delete` / `resolve` 等は1行。

雛形（ヘッダー行のみ）をリポジトリの `scrum/change_log.csv` に置き、`publish.js` で配布する。
**配布先に中身があれば上書きしない**一覧（第5段階で作った `KEEP_IF_EXISTS`）に足す。

## 記録の取り方

3つの書き込み口（`withBacklogWrite_` / `withImpedimentWrite_` / `withCommentWrite_`）で、
**本体の書き込みが成功した後**、同じロックの中で、読み直した行（前）と書いた行（後）から差分を作って追記する。

- 差分は純関数 `diffRows(before, after, fields, ignore)` で作る。`id` をキーに、
  増えた行 → `create`、消えた行 → `delete`、両方にある行 → 違う列ごとに `update`
- 操作の名前（`restore` / `resolve` / `unresolve` / `comment_*`）は、書き込み口が API ごとに決めて渡す。
  差分から推測しない（障害物の解決は「未解決から消えて解決済に増えた」で、差分だけでは削除と区別できない）
- 障害物の解決・取り消しで2ファイル目が途中で止まった（`partial`）ときは、実際に書けた側の差分だけを記録する。
  完了させたときに残りが記録される
- **履歴の追記に失敗しても、本体の書き込みは失敗にしない。** 本体は既に書けている。失敗は握りつぶさず、
  応答に `historyWarning`（「変更履歴を記録できませんでした」）を載せ、画面は全体メッセージに出す
- `change_log.csv` が Drive に無いとき（配布前）も同じく、本体は成功させて `historyWarning` を返す
- 追記は既存の行を解釈し直さない。見出し行だけを検査し、新しい行を文字列のまま末尾に足す（末尾に改行が無ければ補う）
- 追記後のファイルが100万文字を超えたら、記録は成功させたうえで `historyWarning` に切り替えの案内を載せる

## 読み取り

履歴は増え続けるので、ビューの応答には載せない。**パネルを開いて「履歴」を押したときだけ取りに行く。**

```
apiGetHistory(targetId) → { ok, entries: [{ at, actor, action, field, before, after }], truncated? }   // 新しい順、最大200件
```

- ちょうど200件のときは `truncated: true` を付け、画面は一覧の最後に「これより前の履歴は省略しています」と出す

- `targetId` は `^(PBI|IMP)-\d+$` だけ受け付ける
- ファイルが無い・壊れているときは空の一覧（`ok: true`）と、画面に「まだ履歴がありません」
- 削除した PBI の過去の値も、履歴からは読める（同じドメインの閲覧者に限る）

## 差分の見せ方

パネルの下部、コメントの上に「履歴」の節（初めは畳んである。開いたときに読み込む）。

- 1回の書き込み（同じ `at` と `actor`）を1つのまとまりにして、新しい順に並べる。見出しは「日時・書いた人（`@` の前）・操作名」
- `update` は項目ごとに「項目名: 前 → 後」。項目名は画面の言葉に直す（`size` → ポイント 等。用語集と同じ）
- 複数行の値（説明・受入基準・解決策）は**行単位の差分**で見せる。消えた行は取り消し線と `--danger`、
  足した行は `--accent`（どちらも既存のトークン。新しいトークンは作らない）。色だけに頼らず、行頭に「−」「＋」を付ける
- 1行の値は「前 → 後」をそのまま並べる。空は「（空）」
- 行単位の差分は純関数 `lineDiff(before, after)` → `[{ op: 'same'|'del'|'add', text }]`（LCS。各側 500 行を超えたら「前」と「後」を丸ごと並べる）

## API

増える公開関数は `apiGetHistory` の1つだけ。書き込みの API は増やさない。

## アーキテクチャ

| ファイル | 役割 |
|---|---|
| `scrum/change_log.csv`（新） | 雛形 |
| `gas/pure_history.js`（新） | `HISTORY_FIELDS`、`diffRows`、`historyRows(events, meta)`、`historyFor(rows, targetId, limit)`、`lineDiff` |
| `gas/pure_write_guard.js` | 許可リストに `change_log.csv` |

| `gas/kanban.html` | パネルの「履歴」節 |

## テスト

- 純関数: `diffRows`（作成・削除・項目の変更・無視する列・変化なしで空）、`lineDiff`（同じ・足した・消した・入れ替え・上限超え）、`historyFor`（対象で絞る・新しい順・上限）
- `web_app_flow`: 各 API が正しい行を残す（PBI の変更で `updated_at` が出ない、障害物の解決が `resolve` 1行、コメントの本文が残らない）、
  `partial` で書けた側だけ、履歴の書き込み失敗・ファイル無しで本体は成功し `historyWarning`、`apiGetHistory` の形の検査
- DOM シム: 履歴の節は畳んで始まり、開くと1回だけ取りに行く、まとまりと差分の表示、別のパネルへ移った後に届いた応答で描かない、`historyWarning` の表示
- 実ブラウザ: 長い差分でパネルの操作部に届く、はみ出さない

## 実機で確かめること

- PBI を編集・ドラッグ・削除・取り消しした後、履歴に順に出ること
- 2人のアカウントで、書いた人が分かれて出ること
- `change_log.csv` を配布する前でも、編集が普段どおりでき、警告が出ること

## 対象外

- ローカルの Claude Code の直接編集の記録
- 履歴からの巻き戻し（「この版に戻す」）
- 履歴の検索・絞り込み・書き出し
- 古い履歴の削除・ローテーション（行数が問題になってから考える）
- `change_log.csv` の自動の分割・ローテーション。書き込みは既存の行を解釈し直さず末尾に足すが、ファイル全体の読み書きは残る。100万文字を超えたら書き込みのたびに大きさの警告を出し、[docs/setup.md](../../setup.md) の「変更履歴のファイルを切り替える」の手順で手動で切り替える
