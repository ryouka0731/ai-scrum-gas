# AI Scrum Web アプリ 第2段階 設計（PBI の作成・編集・削除 + UI 刷新）

## 背景

第1段階でカンバンとドラッグによる状態変更を作った。しかし**アプリから PBI を起票できない**ため、
人がスプレッドシートやローカルの Claude Code を開かないと使い始められない。

実機で触った結果、次の2点が明らかになった。

- **カードを新規作成できない**
- 見た目が素のままで、業務ツールとして使うには読みづらい

本設計は、人がアプリだけで完結できる状態にする。

## 段階の位置づけ

| 段階 | 内容 | 状態 |
|---|---|---|
| 第1段階 | 双方向同期の基盤 + カンバン | 完了（PR #1） |
| **第2段階（本設計）** | **PBI の作成・編集・削除 + UI 刷新** | 本設計 |
| 第3段階 | コメント・議論のスレッド | 未着手 |
| 第4段階 | 変更履歴と差分表示 | 未着手 |

## 設計の拠りどころ

UI の判断は、社内の登壇資料「SCM 店舗在庫管理領域 UI 改善 設計意図説明資料」の設計論に従う。
具体的なスタイルではなく、方法論として次を採る。

| 原則 | 本設計での現れ方 |
|---|---|
| **オブジェクト指向 UI**（名詞優先、動詞は後付け） | 操作の起点は常にカード。作成も列（＝ステータスという文脈）から生む |
| **モードレス** | 操作を制限しない。詳細を開いたままドラッグできる |
| **フェイルセーフ**（実行確認ではなく実行後に取り消せる） | 削除に確認ダイアログを置かず、即実行して取り消せる通知を出す |
| **横スクロールを避ける** | 狭い画面では列を畳んで縦スクロールにする |
| **無関係操作のリスク無化** | 権限が無いと分かったら、その操作の導線を閉じる |
| **メンタルモデルとの一致** | ドメインの名詞（PBI・ステータス・スプリント）をそのまま画面の構造にする |

## 画面構成

ボードと、右に並ぶ詳細パネルの2ペイン。**パネルはオーバーレイを持たない。**
開いたままカードをドラッグでき、盤面の操作は一切制限されない。

```
┌──────────────────────────────────────┬──────────────────┐
│ AI Scrum ボード        [⟳ 最新にする] │ PBI-003          │
├──────┬──────┬──────┬──────┬─────┤ タイトル          │
│ New 2│Ready2│進行中2│Review2│Done2│ [               ] │
│ ╭──╮ │ ╭──╮ │      │      │     │ 状態 [Ready ▾]    │
│ ╰──╯ │ ╰──╯ │      │      │     │ [💾 保存] [🗑 削除]│
│ ＋   │ ＋   │ ＋   │ ＋   │ ＋  │                  │
└──────┴──────┴──────┴──────┴─────┴──────────────────┘
```

**新規作成は列ごとの「＋」から。** ヘッダーに「＋新規」を置くと動詞が起点になり、
作ったあとでステータスを選ばせることになる。列から生めば、そのステータスが最初から
決まっていて操作が1つ減る。

**狭い画面（幅 900px 未満）では列を縦に積む。** 横スクロールは一覧性を下げ、
操作ステップを増やし、タッチ端末で扱いにくい。列見出しはそのまま残るので、
どのステータスかは失われない。

## 操作とアイコン

アイコンは**インライン SVG を自前で持つ**。外部 CDN は使わない（第1段階の方針を踏襲）。
16px・`fill="none"` + `stroke="currentColor"` にして、文字色に追従させる。
ライト／ダークの切り替えで色指定を書き分けずに済む。

| 操作 | 置き場所 | アイコン |
|---|---|---|
| 新規作成 | 各列の下端 | プラス |
| 保存 | パネル下部 | フロッピー |
| 削除 | パネル下部 | ゴミ箱 |
| 取り消す | 通知バナー | 戻る矢印 |
| 閉じる | パネル右上 | バツ |
| 最新にする | ヘッダー | 円環矢印 |

**ラベルを併記する。** アイコンの意味は利用者によって解釈が割れるため、アイコンだけのボタンは
作らない。SVG には `aria-hidden="true"` を付け、読み上げはラベル側に任せる。

例外は閉じるボタンだけとする。バツ印は解釈が割れず、ラベルを置くとパネルの見出しが窮屈になる。
これには `aria-label="閉じる"` を付ける。

## 見た目の方針

**余白を多めに取り、影で階層を作る落ち着いた業務トーン。** 密度より読みやすさを優先する。

- 外部 CDN を使わず、CSS 変数でトークンを自前に持つ
- 既存の `--line` / `--ink` / `--ink-2` / `--accent` / `--bg` / `--card` を土台に、
  影と間隔のトークンを足す。**新しい変数を入れる前に既存定義を確認し、重複させない**
- ライト／ダーク両対応。`prefers-color-scheme` で切り替える
- 優先度は小さな色付きドットで示す。色だけに意味を持たせず、必ずテキストを併記する（色覚特性への配慮）

日本語が主なので、行間と字詰めは和文向けに調整する。英字前提の値をそのまま使うと詰まって読みづらい。

## API

第1段階の `apiGetBoard` / `apiUpdateStatus` に3つ足す。すべて `LockService` で直列化し、
書き戻しの直前に必ず読み直す（第1段階と同じ）。

| 関数 | 役割 |
|---|---|
| `apiCreatePbi(fields)` | 新しい行を追加する。ID はサーバ側で採番する |
| `apiUpdatePbi(id, fields, expectedUpdatedAt)` | 既存の行を書き換える |
| `apiDeletePbi(id, expectedUpdatedAt)` | 行を削除する。取り消しに使う行の内容を返す |
| `apiRestorePbi(row)` | 削除した行を元の id / created_at のまま戻す |

`google.script.run` から呼ばれるため、この3つは公開のままにする（`_` を付けない）。
**新しく足す内部関数には `_` を付ける。** 付け忘れるとブラウザから直接呼べてしまい、
ロック・検証・競合判定をすべて飛ばせる（第1段階で実際に踏んだ）。

## ID の採番

サーバ側で、**ロックを取ったあと CSV を読み直してから**採番する。
既存の `PBI-(\d+)` のうち最大の数値 + 1 を、元の桁数（3桁ゼロ埋め）で組み立てる。

- アプリ内での同時起票は、ロックで直列化されるので衝突しない
- ローカルの Claude Code が同時に起票した場合は防げない。これはロックの外なのでどの方式でも同じ
- 4桁以上（`PBI-1000`）になったらゼロ埋めせずそのまま伸ばす

採番は純関数（`nextPbiId(rows)`）に置く。GAS 層は自動テストできないため。

## 編集できる項目

| 項目 | 編集 | 備考 |
|---|---|---|
| `title` | 可 | 必須。空なら保存しない |
| `description` | 可 | |
| `acceptance_criteria` | 可 | セミコロン区切りの慣習を保つ |
| `priority` | 可 | Critical / High / Medium / Low から選ぶ |
| `size` | 可 | 数値。空も許す |
| `sprint` | 可 | |
| `status` | 可 | **パネルからも変えられる**（後述） |
| `id` | 不可 | 作成時にサーバが決める |
| `created_at` | 不可 | 作成時にサーバが決める |
| `updated_at` | 不可 | サーバが毎回更新する |

**状態をパネルからも変えられるようにする。** 第1段階ではドラッグのみで、タッチ端末では
操作できないことを既知の制約として文書に残していた。プルダウンを置くことでこれが解消する。
そのために代替 UI を別途作る必要はない。

## 競合の扱い

第1段階と同じ `updated_at` の照合をそのまま使う。画面を描いた時点の値を `expectedUpdatedAt`
として渡し、一致しなければ拒否して最新を見せる。**黙って上書きしない。**

**作成では競合判定を行わない。** 既存の行が無いため照合する対象が無い。ID はロックを取ったあと
読み直した CSV から採番するので、アプリ内で重複することはない。ローカルの Claude Code が
同時に起票して同じ ID を取った場合は防げないが、これはロックの外で起きるためどの方式でも同じで、
第1段階から変わらない制約である。

## 削除

**物理削除にする。** 行を CSV から取り除く。

「完了」は Done 列への移動と `product_backlog_done.csv` で表現するので、削除は
「間違って作った」場合の操作である。この使い分けをパネルの文言に書く。

**確認ダイアログは置かない。** モーダルは操作を制限し順序を固定する。代わりに
**即座に実行し、取り消せる通知を出す**（フェイルセーフ）。通知には消した PBI の ID と
タイトル、そして「取り消す」を並べる。

取り消しは、消した行と同じ内容で作り直すのではなく、**削除前の CSV へ戻すのでもない**。
消えた PBI を `apiCreatePbi` で作り直すと ID が変わり、ローカルの Claude Code が
残した参照が切れる。そこで `apiRestorePbi(row)` を足し、**元の id / created_at を保ったまま
行を戻す**。`updated_at` は戻した時刻で更新する（戻したことも変更だから）。

通知は一定時間で消える。消えたあとは取り消せない。時間内に押さなかった場合に備え、
削除の対象は「間違って作った PBI」であることを画面の文言で伝える
（終わった PBI は Done 列へ移す）。

削除は `expectedUpdatedAt` を照合する（見ていない変更がある行を消させない）。

## 列構成の保護

第1段階と同じく、書き戻しの直前に `assertHeaderMatches(text, BACKLOG_FIELDS)` を通す。
CSV はローカルの Claude Code と共同所有しており、将来列が増えうる。
ヘッダーが想定と食い違ったまま書き戻すと、`BACKLOG_FIELDS` に無い列が黙って消える。

作成時は **`BACKLOG_FIELDS` のすべての列を明示的に埋める**（空文字でよい）。
埋め忘れた列があると `toCsv` の出力で列がずれる。

## 楽観的更新の扱い

第1段階で、応答の到達順により画面がサーバと食い違う問題を直した。
**作成・編集・削除でも同じ仕組みに乗せる。**

**当初、パネルの操作は「1枚のカードの位置」では表せないと考え、送信中はパネルを
開かせない設計にしていた。これは誤りだった。** 作成・編集・削除はいずれも
**ちょうど1枚のカードだけ**を変える。応答の board に写っている他のカードは
サーバがその要求を処理した時点の古い文脈であり、無視してよい。

そこで**すべての操作を「そのカードだけを今の画面に反映する」に統一する**。

- 送信が重なっている間の応答は、board 全体を信じない
- 応答の board からそのカードの位置と内容だけを取り、今の画面へ反映する
  （作成は追加、編集は差し替えと移動、削除は取り除き）
- 送信が1つも重なっていなければ、応答の board をそのまま描く

これにより**オーバーレイも開閉の制限も要らなくなる**。利用者の操作を止めずに
食い違いを防げる。

削除の楽観的更新は行う。押した瞬間にカードを消し、失敗したら戻す。

## テスト

`node --test` で検証するもの（すべて純関数層）。

| 対象 | 確認する内容 |
|---|---|
| ID 採番 | 既存の最大値 + 1 になること。空の CSV で PBI-001 になること。桁が繰り上がること |
| 行の追加 | `BACKLOG_FIELDS` のすべての列が埋まること。既存行が変わらないこと |
| 行の削除 | 対象だけが消えること。`updated_at` が不一致なら拒否すること |
| 行の編集 | 指定した項目だけが変わること。`id` / `created_at` が保たれること |
| 入力の検証 | タイトルが空なら拒否すること。未知の `status` / `priority` を拒否すること |

GAS 層と HTML は自動テストできない。ただし第1段階と同じく、`kanban.html` の
`<script>` を Node の DOM シムで走らせ、**応答の到達順が入り混じったときに画面と
サーバが食い違わないこと**を検査する。読むだけでは見えない不具合が第1段階で
実際に見つかっているため、この検査は作成・編集・削除にも広げる。

## 実機で確かめること

自動テストが届かないもの。

- 詳細パネルの開閉、作成・編集・削除の一連の流れ
- 削除したあと通知から取り消せること。取り消した PBI の ID が変わっていないこと
- 詳細を開いたままカードをドラッグできること（モードレス）
- 幅の狭い画面で列が縦に積まれること
- ダークモードでの表示（`prefers-color-scheme` を切り替える）
- タッチ端末で、プルダウンから状態を変えられること
- ブラウザのコンソールから、`_` 付きの内部関数が呼べないこと
- 閲覧者権限のアカウントで、作成・削除がエラーになり日本語の案内が出ること
