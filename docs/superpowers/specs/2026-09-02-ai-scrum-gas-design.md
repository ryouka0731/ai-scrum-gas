# AI Scrum GAS版 設計

## 背景

現行の `ai-scrum` は、スクラム成果物（`scrum/` の CSV / Markdown）を真実の源泉とし、GitHub Issues / Projects V2 へ一方向同期して可視化していた。同期は GitHub Actions が実行し、Issue 上の `/ask-po` は gh-aw のエージェントが応答していた。

会社の制約により **GitHub と AI の API が利用できなくなった**。利用可能なのは Google Workspace と、各メンバーのローカル PC 上の Claude Code である。

本設計は、GitHub に依存していた「可視化」と「自動化」の2層を GWS + Google Apps Script で置き換える。エージェントとスキル、スクラム成果物の形式は変更しない。

## 制約と前提

- サーバ側で AI を実行できない。エージェントはローカルの Claude Code でのみ動く
- 外部サービスの OAuth 設定はメンバーに要求できない（会社ポリシー）
- Google Drive のデスクトップ同期が利用できる
- clasp と Node.js は開発者（リポジトリ管理者）のローカルで利用できる

## 設計判断

| 論点 | 決定 | 理由 |
|---|---|---|
| 真実の源泉 | `scrum/` のファイル（CSV / Markdown） | 9エージェントがファイル前提で動作する。現行設計を維持し移植コストを最小化する |
| 同期方向 | 一方向（ファイル → Sheets） | 双方向は競合解決が必要になり、スクラムイベント外での状態変更を招く |
| 同期の駆動 | GAS が Drive を直接読む（プル型） | メンバー側に認証設定を一切要求しない。現行で PAT に詰まった構図を繰り返さない |
| スプレッドシート | チームで1つを共有 | チーム全体の単一ボードを保つ |
| clasp の役割 | GAS コードのバージョン管理とデプロイ（管理者のみ） | メンバーは Sheets を開くだけでよい |
| フォルダ配置 | プロジェクトフォルダごと Drive 共有フォルダに置く | `.claude/` と `scrum/` が全員に自動で行き渡る |

## アーキテクチャ

```
[各メンバーのローカル PC]
  Claude Code + 9エージェント / 20スキル
        ↓ 読み書き
  <Drive 共有フォルダ>/ai-scrum-gas/scrum/*.csv, *.md
        ↓ Drive デスクトップ同期
  [Google Drive]
        ↓ DriveApp で読む（読み取りのみ）
  [GAS: 共有スプレッドシートのバインドスクリプト]
        ↓ setValues
  ダッシュボード各シート
```

現行との対応:

| 現行 | GAS版 |
|---|---|
| `scripts/github_project/sync_backlog.py` | GAS のプル型同期（`gas_sync.js`） |
| `.github/workflows/sync-github-project.yml` | 時間主導トリガー + カスタムメニュー |
| GitHub Projects V2 のボード / ロードマップ | Sheets のカンバン / ロードマップタブ |
| GitHub Issues（PBI 詳細 + 人間のコメント） | バックログタブ + 「メモ」列 |
| `/ask-po`（gh-aw エージェント） | **廃止**。ローカルの `/ask-to-po-shuri` で代替 |

## リポジトリ構成

```
ai-scrum-gas/
├── CLAUDE.md                  # GAS版の運用ガイド
├── README.md
├── package.json               # テスト実行のみ（node --test）
├── .gitignore
├── .claude/                   # 現行から移植（9エージェント / 20スキル / hooks）
├── gas/                       # clasp の rootDir
│   ├── appsscript.json
│   ├── .clasp.json.example    # scriptId はセットアップ時に決まるため実体は gitignore
│   ├── .claspignore           # tests/ を push 対象から除外
│   ├── pure_*.js              # GAS API 非依存。node でテストする
│   ├── gas_*.js               # DriveApp / SpreadsheetApp 依存の薄い層
│   └── tests/*.test.js
├── scrum/                     # 成果物テンプレート（現行から移植）
└── docs/
    ├── setup.md               # 管理者向けセットアップ / メンバー向け手順
    └── superpowers/specs/     # 本設計書
```

### 純関数層と GAS 層の分離

GAS は自動テストが難しい。テスト可能性を確保するため、ロジックを GAS API に触れない純関数へ寄せる。

- `pure_*.js`: CSV パース、Markdown 表パース、ひな形行の判定、スプリント名の正規化、各シートの2次元配列を組み立てる変換
- `gas_*.js`: `DriveApp` でファイル本文を取得する、`SpreadsheetApp` で `setValues` する、メニューとトリガーを登録する

純関数はファイル末尾で `if (typeof module !== 'undefined') { module.exports = {...} }` を付ける。GAS では `module` が未定義のためこの行は無害で、Node からは `require` できる。

## Sheets の構造

| タブ | データ源 | 内容 |
|---|---|---|
| ダッシュボード | 各シートの集約 | 現スプリント、スプリントゴール、PBI 進捗サマリ、最終同期時刻 |
| バックログ | `product_backlog.csv` | 全列 + メモ列 |
| 完了バックログ | `product_backlog_done.csv` | 全列 |
| カンバン | バックログ | Status（New / Ready / In Progress / Review / Done）を列に展開 |
| ロードマップ | `velocity.csv` の期間 × PBI の `sprint` | 日付軸に条件付き書式で帯を描く |
| ベロシティ | `velocity.csv` | 表 + 折れ線グラフ（計画 / 完了 / 持ち越し） |
| バーンダウン | `sprintXXX/sprint_backlog.md` の `## バーンダウン` 表 | 表 + 折れ線グラフ |
| 障害物 | `impediment_log.csv` + `impediment_log_resolved.csv` | 未解決を上に、解決済みを下に |
| 同期ログ | 実行時 | 同期時刻、読んだファイル、スキップしたもの、警告 |

## 同期の仕様

### 起動契機

- スプレッドシートのカスタムメニュー「AI Scrum」→「今すぐ同期」
- 時間主導トリガー 30分毎（Drive デスクトップ同期のラグを吸収する）

いずれも同じエントリポイント `syncAll()` を呼ぶ。

### 設定

Drive 共有フォルダのフォルダ ID をスクリプトプロパティ `SCRUM_FOLDER_ID` に保存する。コードには埋め込まない。メニューから設定用ダイアログを開ける。

### 冪等性と手書きメモの保護

各シートは毎回、既存の値域をクリアしてから再構築する。全消し→再構築が最も単純に冪等性を担保できる。

ただしそれだけでは、現行の「マーカー外に書いた人間のコメントは保持される」に相当する逃げ場が無くなる。そのため**キーを持つシートにだけ**右端に「メモ」列を設け、再構築の直前に「キー → メモ」の対応を読み出し、再構築後に書き戻す。

| シート | メモ列 | キー |
|---|---|---|
| バックログ | あり | PBI の `id` |
| 障害物 | あり | `id` |
| 完了バックログ / カンバン / ロードマップ / ベロシティ / バーンダウン / ダッシュボード / 同期ログ | なし | — |

カンバンとロードマップはバックログの派生表示であり、書き込む場所はバックログのメモ列に一本化する。同じ内容を複数箇所で編集できると、どれが正か分からなくなるためである。

メモ列以外のセルは次回同期で上書きされる。これは一方向同期の原則どおりで、ドキュメントに明記する。

### ひな形行の除外

現行 `sync_backlog.py` の判定を移植する。次のいずれかに当てはまる行は同期対象外とする。

- タイトルが全角括弧で囲まれている（`（PBIタイトル）` など）
- 日付が `YYYY-MM-DD` のまま
- `priority` が `Critical/High/Medium/Low` のような複合値

### スプリント名の正規化

`product_backlog.csv` の `sprint` 列は `Sprint 001`、`velocity.csv` は `sprint001` と表記が揺れる。現行で実際に踏んだ不具合であるため、同じ正規化を移植する。空白・アンダースコア・ハイフンを除去して小文字化し、末尾の連番を3桁ゼロ埋めに揃えて突き合わせる。

### エラー処理

部分的な失敗で全体を止めない。

| 状況 | 挙動 |
|---|---|
| `SCRUM_FOLDER_ID` 未設定 | セットアップ手順を示して停止する |
| フォルダにアクセスできない | 同上 |
| CSV が見つからない | そのシートだけスキップし、同期ログに警告を残して続行する |
| CSV の列が想定と違う | そのシートだけスキップし、警告を残す |
| `## バーンダウン` 表が無い | バーンダウンのみスキップする |
| 同期中の例外 | 同期ログに記録し、処理済みのシートは残す |

### 実行時間

読み取り対象は数十 KB のテキストで、GAS の6分制限に対して十分小さい。書き込みは `setValues` で1シート1回のバッチにまとめ、セル単位の書き込みを避ける。

## テスト

`node --test` で純関数層を検証する。GAS 依存層は薄く保ち、手動確認に委ねる。

| 対象 | 確認する内容 |
|---|---|
| CSV パーサ | 引用符内のカンマ、改行、BOM、空行 |
| Markdown 表パーサ | 見出しアンカーからの抽出、表が無い場合、区切り行の扱い |
| ひな形行判定 | 全角括弧タイトル、`YYYY-MM-DD`、複合値 priority |
| スプリント名正規化 | `Sprint 001` / `sprint001` / `sprint-1` / `SPRINT_1` が一致すること |
| 各シートの変換 | 入力 CSV から期待する2次元配列が得られること |
| メモ列の引き継ぎ | キー一致で保持され、行の増減と並べ替えに追従すること |

## 現行からの後退

`/ask-po` に相当する「Issue 上での PO 対話」は、サーバ側で AI を実行できないため実現しない。相談はバックログのメモ列に書き、メンバーがローカルの Claude Code で `/ask-to-po-shuri` を実行し、結果を `scrum/` の成果物へ書き戻す運用とする。専用の「相談」列は設けない。列を増やすより、既に保護対象であるメモ列に寄せる方が仕組みが1つで済む。

## セットアップ

### 管理者（1回のみ）

1. Drive 共有フォルダを作り、`ai-scrum-gas` プロジェクトフォルダごと配置する
2. 共有スプレッドシートを作成する
3. `clasp login` の後、`gas/.clasp.json.example` を `gas/.clasp.json` にコピーし、スプレッドシートにバインドしたスクリプトの `scriptId` を書いて `clasp push` する
4. メニュー「AI Scrum」→「設定」でフォルダ ID を登録する
5. メニュー「AI Scrum」→「トリガーを設定」で30分毎のトリガーを作る

### メンバー

1. Drive デスクトップ同期で共有フォルダを取得する
2. 同期されたフォルダで Claude Code を起動する
3. ダッシュボードは共有スプレッドシートを開くだけで見られる

## 対象外

- Sheets からファイルへの逆流（双方向同期）
- GAS 上でのエージェント実行
- Google Chat / Gmail 通知
