# セットアップ

## 管理者（テナントごとに1回）

このリポジトリは複数の Google Workspace テナントで使い回せます。テナント固有の値は
リポジトリに含まれないため、clone した状態から次の手順で一から作れます。

**このリポジトリ（`.git` を含む）は Google Drive の外に clone してください。** Drive 同期フォルダの中で
git を操作すると、コミット中に書き換わる `.git` 配下を Drive が配りにいって競合コピーができ、
リポジトリが壊れます。メンバーは会社の制約で GitHub を使えず `.git` を必要としないため、
メンバーに渡すファイルは `scripts/publish.js` で Drive の共有フォルダへ別途配布します。

パソコンに Node.js がインストールされている必要があります（`scripts/setup.js` `scripts/publish.js` の実行に使う）。
どちらも Node.js 製のため、Mac / Windows どちらの管理者でもそのまま動きます。

1. [Apps Script の設定](https://script.google.com/home/usersettings) を開き、「Apps Script API」を
   オンにする。このテナントで初めて使うときに必須で、オフのままだと次の手順が
   `User has not enabled the Apps Script API` で失敗する
2. Google Drive に共有フォルダを作る（手順1で clone したリポジトリとは別の、Drive 上のフォルダ）
3. `.claude` `scrum` `CLAUDE.md` `README.md` をその共有フォルダへ配布する

   ```bash
   node scripts/publish.js "<共有フォルダのパス>"
   ```

   配布先に無いファイルは追加、既にあるファイルは上書きされる。配布先にしか無いファイル
   （メンバーが `scrum/` に作った `sprintXXX/` などの成果物）は消えない。配布記録として
   `scrum/.published.json` を書き、内容はダッシュボードの「配布日時」に表示される

4. スプレッドシート・Apps Script プロジェクト・Web アプリを作る

   ```bash
   node scripts/setup.js "AI Scrum Board"
   ```

   ログインしていなければブラウザが開きます。完了すると
   スプレッドシートの URL が表示されます。

   （`clasp create` はリモートの空マニフェストで `gas/appsscript.json` を上書きする
   仕様があるが、`scripts/setup.js` が直後に自動で元へ復元するため手作業は不要）

   このスクリプトは最後に `clasp create-deployment` で Web アプリのデプロイも自動で行う。
   **個人の Google アカウントでは、この自動デプロイがエラーになる。** `gas/appsscript.json` の
   `webapp.access` を組織内限定の `DOMAIN` にしているためで、個人アカウントには「組織」が無く
   `DOMAIN` を選べない（詳しくは後述の「Web アプリの公開範囲」を参照）。エラーになった場合、
   スプレッドシート自体は使える状態のため止まらず、次のいずれかで進める。
   - 検証目的なら、`gas/appsscript.json` の `access` を一時的に `MYSELF` に変更してから
     `cd gas && npx @google/clasp@3 push` → `npx @google/clasp@3 create-deployment -d "AI Scrum ボード"`
     を実行する。**この変更はコミットしない**こと（テナントの本番運用では `DOMAIN` に戻す）
   - 組織アカウントで検証する、または後述の「手動でデプロイする」を Apps Script の画面から行う

5. **作成されたスプレッドシートをチームへ共有する**。`scripts/setup.js` は
   マイドライブ直下に作るため、この操作をしないとメンバーは開けない
   1. 表示された URL を開く
   2. Google ドライブでそのファイルを手順2の共有フォルダへ移動する
      （ドライブの一覧で右クリック →「整理」→「移動」）
   3. 「共有」からチームのメンバーに**閲覧者**（メモ列を書いてもらう場合は**編集者**）を付ける

6. 表示された URL を開き、メニュー「AI Scrum」→「設定（Drive フォルダ ID）」で
   手順2の**共有フォルダ**の ID を登録する（`scrum` フォルダの ID ではない。共有フォルダの直下に
   `scrum` フォルダがある状態にする）
7. 「今すぐ同期」を実行し、9枚のシートができることを確認する。初回は Drive の
   読み書きを求める承認ダイアログが出るので、内容を確認して許可する
8. 「自動同期を有効にする（30分毎）」を実行する
9. **Web アプリの URL をメンバーに共有する。** URL は Apps Script の画面（手順4の完了メッセージ、
   またはスプレッドシートのメニュー「拡張機能」→「Apps Script」から開ける）の左メニュー
   「デプロイ」→「デプロイを管理」で確認できる。PBI の作成・編集・削除・状態変更は
   この URL から行う（それ以外の情報の閲覧は、これまで通り共有スプレッドシートを使う。
   Web アプリはカンバンのみを扱うため）

メニューが出ないときはスプレッドシートを開き直してください。

### 手動でデプロイする

手順4の自動デプロイに失敗した場合、または再デプロイが必要な場合は、Apps Script の画面から行う。

1. Apps Script の画面を開く（スプレッドシートのメニュー「拡張機能」→「Apps Script」）
2. 右上の「デプロイ」→「新しいデプロイ」
3. 種類の選択（歯車アイコン）で「ウェブアプリ」を選ぶ
4. 「次のユーザーとして実行」は「アクセスしているユーザー」、
   「アクセスできるユーザー」は「（組織のドメイン名）」のままにする
5. 「デプロイ」を押す。表示された URL がメンバーへ共有する Web アプリの URL

コードを更新したあとに URL を変えずに再デプロイしたい場合は、「デプロイを管理」から
既存のデプロイの鉛筆アイコンを押し、バージョンを「新バージョン」にして更新する
（`npx @google/clasp@3 create-deployment -i <デプロイID>` でも同じことができる）。

### `.claude` や `scrum` を更新したとき

再配布しないとメンバーの手元には届かない。

```bash
node scripts/publish.js "<共有フォルダのパス>"
```

### 既にあるスプレッドシートに載せる場合

`scripts/setup.js` は新規作成専用です。既存のスプレッドシートを使うときは、
そのスクリプト ID を `gas/.clasp.json` に書いて `cd gas && npx @google/clasp@3 push` します。
`gas/.clasp.json.example` を雛形として使ってください。このファイルは
テナント固有の値を含むため git 管理しません。この経路では自動デプロイが走らないため、
続けて前述の「手動でデプロイする」を行ってください。

### Drive への書き込み権限が変わったこと（`oauthScopes`）

第1段階（Web アプリのカンバン）から、`gas/appsscript.json` の `oauthScopes` を
`drive.readonly`（読み取り専用）から **`drive`（利用者の Drive 全体への読み書き）** に広げた。
カンバンで PBI の状態を変えたとき、Drive 上の `scrum/product_backlog.csv` へ書き戻す必要が
あるため。`drive.file`（アプリが作成したファイルのみ）では既存の CSV を開けず使えない。

書き込みが際限なく広がらないよう、コード側で書き込み先を絞っている。
`gas/pure_write_guard.js` の許可リスト（`WRITABLE_FILES`）に無いファイル名は
`writeScrumFile_()`（`gas/gas_drive_write.js`）が例外を投げて拒否する。現在許可しているのは
`scrum/product_backlog.csv` の1つだけである。

**既に運用中のテナントをこのバージョンへ更新する場合、スコープが増えるため、
メンバーは次に Web アプリを開いたときに再度承認画面を求められる。** 事前に
「今回から権限の確認画面がもう一度出る」と周知しておくとよい（[README.md](../README.md) にも
案内を書いてある）。

### 日本以外のテナントで使う場合

`gas/appsscript.json` の `timeZone` を、そのテナントのタイムゾーンに変更してから push する。
同期時刻の表示に使われる。

### コードを更新したとき

```bash
cd gas && npx @google/clasp@3 push
```

## メンバー

1. Google ドライブのデスクトップ アプリで共有フォルダを同期する
2. 同期されたフォルダで Claude Code を起動する
3. PBI の作成・編集・削除・状態の確認・変更は、共有された Web アプリの URL を開いて
   カンバンで行う
4. ベロシティ・バーンダウン・ロードマップ・障害物・ダッシュボードなど、カンバン以外の情報は
   引き続き共有スプレッドシートを開いて見る（**編集はしない**。次回同期で失われる。
   メモ列のみ例外）

Web アプリはカンバン（PBI の作成・編集・削除・状態変更）のみを扱う。それ以外の情報を
Web アプリへ移すのは今後の段階。

パスワードは不要だが、**見るだけの人も含めて全員**、初回だけ Drive の読み書きを
求める承認ダイアログが出る（後述）。名前でファイルを探して読み書きするため
`drive.file`（アプリ作成ファイルのみ）では足りず、`drive`（Drive 全体）への
同意が要る。

## 制限

- **配布を忘れてもエラーにならない**。`.claude` や `scrum` を更新して再配布し忘れると、
  メンバーは古いままの内容を使い続ける。ダッシュボードの「配布日時」で気づける
- シートの再構築（読み取り同期）は **ファイル → スプレッドシート** の一方向である。
  スプレッドシート側の編集は次回同期で失われる。ただし「バックログ」と「障害物」の
  **メモ列**だけは ID をキーに引き継がれる
- カンバンでの状態変更（書き戻し）は即座に CSV へ反映されるが、**スプレッドシートのシート自体は
  再構築されない**。シートへの反映は既存の同期（「今すぐ同期」または30分毎）のタイミングになる。
  書き戻しのたびに9枚全部を作り直すと操作が重くなるための設計判断
- 反映までの時間は Drive デスクトップ同期のラグ + トリガー間隔（最大30分）になる。
  すぐ見たいときはメニューの「今すぐ同期」を使う
- **メモ列が引き継がれるのは、その ID が一覧に残っている間だけ**である。項目が完了バックログへ
  移るとメモ列自体が無くなり、元ファイルから行が消えた場合も引き継がれない。
  残したい内容はファイル側へ書き移す
- 「今すぐ同期」と自動同期、および Web アプリでの書き戻しは、**実行した人の Google Drive 全体への
  読み書き権限**（`oauthScopes` の `drive`）を求める。初回実行時に承認ダイアログが出る。
  フォルダ ID 指定で読むには `drive.file` では足りないため、スコープを絞ることはできない。
  ただしコード側で書き込み先を `scrum/product_backlog.csv` のみに限定している
  （詳しくは前述の「Drive への書き込み権限が変わったこと」を参照）
- Web アプリのカンバンは PC・スマホ・タブレットのいずれからも操作できる。ただし
  ドラッグ&ドロップによる状態変更はスマホ・タブレットでは使えないため、その場合は
  カードを開いてプルダウンから状態を選ぶ
- Web アプリの公開範囲は組織内（`webapp.access: DOMAIN`）に限定している。URL を知っているだけの
  組織外のユーザーは開けない
- PO への相談はバックログのメモ列に書き、ローカルの Claude Code で `/ask-to-po-shuri` を実行する
